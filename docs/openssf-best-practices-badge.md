# OpenSSF Best Practices Badge: answer sheet (Passing and Silver)

The working script for the project's
[OpenSSF Best Practices Badge](https://www.bestpractices.dev/projects/15281)
entry (project 15281). It maps every **Passing** (level 0) and **Silver**
(level 1) criterion to a status (**Met** / **N/A** / **Unmet**), a
justification to paste into the form, and the evidence URL the form asks for,
so the questionnaire can be filled in and re-certified later without
re-deriving the rationale. Criteria ids and levels follow the authoritative
[`criteria.yml`](https://raw.githubusercontent.com/coreinfrastructure/best-practices-badge/main/criteria/criteria.yml).

- **Target:** Silver (the form awards Passing first; Silver layers on it).
- **Repository:** <https://github.com/DocGerd/cockpit-procedure-trainer>
- **Homepage:** <https://docgerd.github.io/cockpit-procedure-trainer/>. The
  GitHub Pages site is the delivered product (HTTPS enforced, built from
  `main`), so it is the project homepage; the repository URL is the source.
  The repository's GitHub homepage field holds the same URL; keep the form's
  homepage URL matching it.
- **Default branch:** `develop` (evidence URLs below point at it).
- **License:** MIT (`LICENSE` at the root).
- **Language:** TypeScript (React, Vite, pnpm workspaces).
- **Crypto:** none. A client-only static web app with no accounts, no backend
  and no runtime network call beyond its own origin; every `crypto_*` criterion
  that asks about a security mechanism of the project's own is **N/A**, and the
  ones about transport are delegated to the browser.

> **MUST / SHOULD / SUGGESTED:** only an unmet **MUST** (or an unmet **SHOULD**
> without a justified exception) blocks a badge. Every MUST below is **Met** or
> legitimately **N/A** (N/A only where the criterion allows it). The Unmet
> items are `dco` and `bus_factor` (SHOULD) and `version_tags_signed`
> (SUGGESTED); each carries its reason and none blocks Silver.

> **Volatile figures.** Counts, percentages and dates decay. Where a criterion
> needs a figure, the row says "as measured when submitted" and names the
> command; re-run it on the day of submission and paste the fresh value.

## 0. Items that need the owner's action

Everything else is paste work. These need a human:

1. **Cut a release after the signing change (#373) and verify it before
   submitting `signed_releases`.** v0.11.0 and earlier carry no signed asset.
   After the next release PR is merged, wait for the Release workflow, then
   run the two commands in
   [`docs/verifying-a-release.md`](verifying-a-release.md)
   (`gh release download …` and `gh attestation verify …`). Only once that
   prints a matching attestation is the `signed_releases` row true as written.
2. **Self-attestations.** Only the maintainer can truthfully assert these;
   they are all true as of the evidence cited: `know_secure_design`,
   `know_common_errors`, `implement_secure_design`, `documentation_current`,
   `access_continuity`, `regression_tests_added50`.
3. **Measure the volatile figures on submission day** and paste them into the
   rows marked "as measured when submitted": `test_statement_coverage80`
   (`pnpm test:coverage`), `regression_tests_added50` (method in the row),
   `build_repeatable` (build twice, `diff -r`), `maintained` (date of the
   latest commit and release).
4. **Non-blocking gaps, decided, not forgotten:** `dco` (declined in
   `GOVERNANCE.md`), `bus_factor` (genuinely 1), `version_tags_signed`
   (artifact attestation instead of signed tags). Leave them Unmet with the
   one-line reasons below.
5. **Contact email.** Concerns the form's project contact field (the
   address the form lists for questions about the project, separate from the
   `vulnerability_report_*` criteria). Options: a public maintainer address
   (the Git author email), or leave the field empty if the form allows it.
   GitHub private vulnerability reporting needs no email; vulnerability reports
   go through it, not email (`SECURITY.md`).
6. **After the award**, swap the README badge to the level variant the form
   offers, and add the Silver badge once it is granted.
