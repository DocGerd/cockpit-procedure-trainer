# M1 Design Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The product brand, the screen brief and the design handoff are written down, and the design is locked in code: one tokens file, a lint rule that rejects colour, type and spacing literals elsewhere in the web app, and bundled fonts. M0's carried findings are disposed of and the Dependabot fragment exemption is documented. Released as v0.2.0.

**Architecture:** Docs under `docs/design/` (`BRAND.md`, `brief.md`, `handoff/`). `BRAND.md` is the source of truth for every value the code depends on; `apps/web/src/styles/tokens.css` reproduces it and a test keeps the two equal. ESLint (TS/TSX) and Stylelint (CSS) reject literals in `apps/web/src` outside `tokens.css`. Fonts come from Fontsource packages and are bundled by Vite.

**Tech Stack:** as M0, plus Stylelint and the `@fontsource/geist` and `@fontsource/geist-mono` packages (both OFL-1.1).

**Spec:** `docs/superpowers/specs/2026-10-05-cockpit-procedure-trainer-design.md`, sections 2 (Visual design row), 4.8, 5 (Screen), 6 and 11 (M1 Design).

**Issues:** #7 BRAND.md, #8 design brief, #9 handoff export, #10 lock design, #71 carried M0 findings, #75 Dependabot fragment exemption. All six are in the M1 milestone; the release needs every one closed.

## Global Constraints

- Base branch `develop`. One issue, one branch, one PR with `Closes #<n>`. Agents never merge into `main`.
- Every PR adds `changelog.d/<issue>.<category>.md`. Categories: `added`, `changed`, `deprecated`, `removed`, `fixed`, `security`.
- Every PR is reviewed by a separate agent with the `pr-selfreview` skill: one inline thread per finding, fix, resolve every thread. Then `merge-train`.
- Colours, type and spacing come only from `apps/web/src/styles/tokens.css`.
- The brand styles the app frame (header, checklist pane, outside-view frame, tabs, dialogs), never the cockpit panel. Status inks never appear on the panel. The one brand colour allowed over the panel is the accent, as the Guided highlight overlay (spec §6.2), always paired with a shape cue.
- No handbook scans or manufacturer artwork in the repo.
- Nothing committed, and no issue or PR text, contains local absolute paths, machine or user names, personal tool names, or links to private artifacts. The owner's design canvas is referred to as "the product's design canvas", never by URL.
- Comments and docs: only what the code cannot say. No dates, durations or measured figures (contrast ratios included) unless they are requirements.
- Shell scripts that call `gh`: `timeout -k 5 60 gh … </dev/null`; `mapfile` + `for`, never `while read` around a spawned command. `gh api` takes `--raw-field`/`--field`, spelled out.
- Commit identity and trailers as in M0: author `13460098+DocGerd@users.noreply.github.com`; the `Co-Authored-By:` line named by the running harness; PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- UI-visible PRs (#10, #71) get a real-browser pass at tablet and desktop width (`ui-verifier`).
